# Five advisor answers (anonymized, shuffled)

## Advisor 1
P vs Q, 4-day plan. P: Day 1 FalkorDB+schema+MCP server (~6 tools), TS import parser; Day 2 hooks, parallel-safe query, briefing, graph viewer; Day 3 live 3-agent demo, kill/resume, why-path. Hardest: the demo, not the graph — 3 real agents are nondeterministic; hooks break across Claude Code versions. Credits: product ~0 LLM; demo rehearsals ~3 agents × 50–100k tokens ≈ $3–8 each, 10 rehearsals $30–80, risky. Day-3 failure fallback: scripted fake agents → looks staged. Deployment awkward (public MCP needs auth). Q: Day 1 GitHub API → FalkorDB for one mid-size repo (~2k PRs; 5,000 req/h), deterministic "who knows this file" with no LLM. Day 2 Haiku decision extraction with provenance, similar-issue via vector index, corrections. Day 3 triage agent, drafted reply, highlighted path, polling. Hardest: extraction quality. Credits ≈ $5–10, $80+ headroom. If day 3 fails, the day 1–2 graph is already a valid submission; frozen-snapshot demo is deterministic; read-only deploy easy. Pick Q: degrades gracefully. Missed: if Q uses FalkorDB's repos the judges are the graph — validate expert claims vs CODEOWNERS; make corrections the demo highlight. P's natural data (builder's own agent graph) costs a day to polish.

## Advisor 2
Flaws P: demo fragile and nondeterministic; scripted multi-agent looks fake. The graph is quietly removable — claims/log/lessons are SQLite/JSON; only import-dependency conflict needs traversal. Crowded and thin real use: mcp_agent_mail, beads, Claude Code agent teams/worktrees, Zep/Graphiti; people isolate agents in worktrees; the real user is mostly the builder. Flaws Q: the default Company Brain entry many will build; Dosu ships OSS triage with citations, CodeScene sells knowledge maps. Extraction eats days and dollars; wrong "decisions" on the judges' own repo backfire; incremental + corrections may slip. Demo generic — a drafted reply is a chatbot screenshot unless there's a surprise insight ("CODEOWNERS is wrong, here's proof"). Pick P narrowly: its two graph-only moments make the graph visibly central and fit "Context for AI Agents" better than Q's crowded track; condition: deterministic demo, Cypher on screen. Missed: the AI-generated-rejection rule hits P harder (AI swarm building AI-swarm tool → "what did you contribute?"); flip it by running P on its own build to prove human direction.

## Advisor 3
Built-with-itself P: connect the builder's own build agents to P on day 1, so by Saturday the graph holds 4 days of real claims, conflicts, decisions and handoffs; the demo shows real history, not a toy. Per-tenant graphs + concurrency reach Connected Data; "why" brushes Company Brain. Q upside: run it on FalkorDB's own repos (judges own the data — strong but double-edged) and package as a GitHub Action/bot for maintainers; but "chat with your repo" is the most crowded idea and Dosu exists. Pick P (built with itself): usefulness shown not argued; the builder is the user; 4 days of real build history is uncopyable; aims at PS5 (preferred). Missed: in P the graph is proof of human contribution — orchestrator decision nodes show human direction; Q has no equivalent answer to the AI-generated rule.

## Advisor 4
P: real problem, but only "does my file transitively depend on a claimed file" truly needs a graph; claims = table, lessons/decisions = notes/vector store, log = append-only table. Possibly the wrong problem: worktrees + merges remove most claiming; CLAUDE.md does briefing. On demo day the graph holds only a few minutes of 3 agents' writes — small, sparse, looks like decoration. Q: core questions are graph questions (weighted person→PR→file→component walk; similar bugs via shared files/components; best reviewer as ranked path); remove FalkorDB and nothing survives; thousands of real nodes make the graph and Cypher carry weight. Weak spot: LLM decision extraction is noisy — make it supporting, not the centerpiece. Dosu proves demand. Pick Q: the graph is the product; in P it's a KV store plus one traversal. Missed: P is in the crowded track (event is literally "Context for AI Agents") while Company Brain needs real ingestion that scares weak teams; timestamped corrections hit "keeping knowledge current" and few will do it; FalkorDB's repos let judges verify every answer.
