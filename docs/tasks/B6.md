## Steps
### Shared
1. `packages/core/src/agent-id.ts`: `agentId(cwd?)` → `process.env.SB_AGENT` or `git -C cwd rev-parse --abbrev-ref HEAD` (trim), else `"unknown"`. One function, both surfaces use it.
2. `queries/agents.ts` (Cypher lives here):
   - `registerAgent(g, { id, kind?: 'cursor'|'claude'|'human' })` — one write: MERGE Agent, SET status=active / lastSeen / startedAt on create, record `register` event.
   - `heartbeat(g, { id })` — SET lastSeen, `heartbeat` event.
   - `status(g)` — `{ agents: [{id, kind, status, lastSeen, claims: string[]}], claims: [{agent, path, until, taskId}] }` of **active** claims (`until > now`). Read-only.
3. Tests against a real FalkorDB (`sb_test_agents`): register, heartbeat updates lastSeen, status lists the claim after `claim()`.

### M7 MCP (`packages/mcp`)
1. Dependency: `@modelcontextprotocol/server@^2.3.1`. Read its README in `node_modules` for the exact `registerTool` / `StdioServerTransport` API — don't guess. Zod only if the SDK requires it; if it does, `zod` v4 is the match. No other deps.
2. Tools (stdio). Agent id = `agentId()`. Each tool connects, runs, closes (or keep one connection for the process lifetime — either is fine).
   - `register_agent` `{ kind?: string }`
   - `claim` `{ paths: string[], task?: string, intent?: string }` → text: `OK until=<iso>` or `CONFLICT\n<type> <file> ← <agent> via <path joined by →>`
   - `release` `{ paths?: string[] }`
   - `heartbeat` `{}`
   - `status` `{}` → a short text listing agents and active claims
3. Entry: `packages/mcp/src/index.ts` starts the stdio server when run. Root or mcp package script is fine; `.cursor/mcp.json` must launch it with `npx tsx` or `node` + tsx so Cursor can start it from the project root.
4. Add to `.cursor/mcp.json` and `.mcp.json`:
   ```json
   "switchboard": { "command": "npx", "args": ["tsx", "packages/mcp/src/index.ts"] }
   ```
   Keep `sb-echo`.

### M8 CLI (`packages/cli`)
1. No extra CLI framework. `process.argv` is enough.
2. `bin`: `switchboard` → the CLI entry. Root script `"switchboard": "tsx packages/cli/src/index.ts"` so `npx tsx packages/cli/src/index.ts …` and `npm run switchboard -- …` both work.
3. Commands (cwd is the repo the agent is in; `--agent` overrides):
   - `parse [dir]` — wrap existing `parseRepo` + `loadParse` (default `demo-repo`)
   - `claim <file…> [--task T] [--intent …]`
   - `release [file…]`
   - `check <file>` — `findConflicts` only, **do not write a claim**. Print the path. Exit **0** if empty, **2** if conflict (so hooks can deny).
   - `edited <file>` — `recordEdit`
4. On conflict, print one line per conflict: `CONFLICT UPSTREAM ui/LoginForm.tsx ← A via ui/LoginForm.tsx → api/login.ts → auth/session.ts → lib/crypto.ts`.
