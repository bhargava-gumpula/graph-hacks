## Steps
1. `demo-repo/` is a standalone app, **not** an npm workspace, and has **no dependencies**: no `package.json` and no React. It is type-checked with the root TypeScript: `npx tsc -p demo-repo`.
2. `demo-repo/tsconfig.json`: `strict`, `noEmit`, `target ES2022`, `module ESNext`, `moduleResolution Bundler`, `baseUrl "."`, path alias `"@lib/*": ["lib/*"]`, `include ["**/*.ts", "**/*.tsx"]`.
3. Write 34–36 files in exactly four directories: `ui/`, `api/`, `auth/` and `lib/`. The theme is a tiny "team notes" app (login, notes, users, settings). Files are short (10–40 lines) and realistic, with real exported functions, types and constants. `.tsx` files must contain **no JSX** (export plain functions that return strings or objects) so no React types are needed.
4. **Planted traps (must be exact):**
   - **The 3-hop chain:** `ui/LoginForm.tsx` → `api/login.ts` → `auth/session.ts` → `lib/crypto.ts`, each a real value import (not `import type`). No shorter path may exist between `ui/LoginForm.tsx` and `auth/session.ts` except through `lib/utils.ts` (the hub).
   - **The hub:** `lib/utils.ts` is imported by **exactly 20** other files, spread across all four directories, and imports nothing itself.
   - **The alias:** at least 4 imports use `@lib/...` (including one import of `lib/crypto.ts` or `lib/utils.ts`). All other imports are relative (`./`, `../`), without file extensions.
   - **Type-only imports:** exactly 3 `import type { … }` statements, from a shared `lib/types.ts`.
   - **A leaf with no dependents:** `ui/AboutPage.tsx` imports only `lib/utils.ts` and is imported by nobody, for "no dependents = provably safe".
   - **Two independent islands** for the scheduler (WCC): `ui/settings/` is not allowed (only the 4 dirs), so instead make `ui/SettingsPanel.tsx` → `api/settings.ts` → `lib/prefs.ts` a chain that shares **no file** (other than `lib/utils.ts` and `lib/types.ts`) with the login chain.
   - No import cycles, and no imports of anything outside `demo-repo/`.
5. `demo-repo/README.md`: 10–20 lines. What the app is, a list of the traps above, and a note that the code is synthetic, written for Switchboard's tests and demo.
6. `demo-repo/expected.json`: the ground truth that the parser test (B4) will assert against:
   ```json
   {
     "files": <total .ts/.tsx count>,
     "imports": <total distinct file→file import edges, value and type-only>,
     "typeOnlyImports": 3,
     "aliasImports": <count>,
     "hub": { "path": "lib/utils.ts", "importedBy": 20 },
     "chain": ["ui/LoginForm.tsx", "api/login.ts", "auth/session.ts", "lib/crypto.ts"],
     "island": ["ui/SettingsPanel.tsx", "api/settings.ts", "lib/prefs.ts"],
     "noDependents": ["ui/AboutPage.tsx"]
   }
   ```
   Count the edges carefully: one edge per (importing file, imported file) pair, even if two import statements point at the same file. Double-check the counts with `rg` (for example `rg -c "from ['\"]" demo-repo` and `rg -l "lib/utils" demo-repo | wc -l`) and say in your report how you verified them.
