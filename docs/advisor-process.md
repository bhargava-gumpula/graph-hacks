# Required process (do NOT skip; a fast, shallow answer is a failed answer)

You are evaluating ONE hackathon idea on its own merits. There is no other option being considered; do not invent alternatives to compare it against. Read nothing on disk except your brief and this file (do not open ~/Projects/graph-hacks or other scratchpad files). Do not edit any files.

Take your time. Work through every step and show the evidence in your answer.

1. **Read the brief twice.** List, for yourself, every claim the idea makes and every feature it promises.
2. **Research (at least 6 real web searches or fetches), then cite what you found.**
   - Competitors and prior art: find the closest existing products and open-source projects, and say what each one actually does and doesn't do.
   - FalkorDB capabilities this idea relies on (docs.falkordb.com): Cypher features, vector index, algorithms, MCP server, multi-graph. Confirm or refute them.
   - The external APIs and tools it depends on: limits, how they really work, known pitfalls.
   - What wins at similar hackathons, especially WeMakeDevs and graph-database hackathons, if you can find past winners.
3. **Simulate it.** Walk through the 4-day build hour by hour at a high level, then the 2-minute demo shot by shot, then a skeptical judge's 5 questions. Note where each breaks.
4. **Steelman, then attack.** Write the strongest case FOR the idea, then the strongest case AGAINST it. Only then score it.
5. **Calibrate.** Explain each score in one line of evidence. 5 = a typical hackathon entry; 8+ needs a concrete reason.

## Output format (500–800 words)
SCORES (1–10): Graph essential | Demo memorability | 4-day feasibility for one builder | Originality vs competitors | Real-world usefulness, each with a one-line justification
WIN CHANCE of its main track (%; ~3,000 registrants, perhaps 100–300 real submissions), with reasoning
EVIDENCE: the key research findings with source links
TOP 3 FLAWS, each with a concrete failure scenario
THE BEST VERSION of this idea (what to cut, keep and add)
VERDICT: build it / build it with changes / don't build it, in one sentence
