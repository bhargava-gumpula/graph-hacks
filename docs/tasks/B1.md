# B1: Day-0 tests (S3 hook and MCP probes, S5 run them and record the results)

- **Goal:** find out, on this machine, which Cursor and Claude Code hooks fire, whether each editor can block an edit, whether both can call a project MCP tool, and whether FalkorDB's algorithms run. The answers decide F11/F12 (block vs log-only) and whether workers use MCP or the CLI (PLAN §2.1).
- **Model:** Opus 5.5 (main chat), with the owner for the in-editor steps.
- **Branch:** `hack/B1`. Worktree: no (hooks must be in the folder Cursor has open).
- **Read first:** PLAN §2.1, §5 "P0 Setup" Day-0 tests 1–4.

## Files you may touch
- `.cursor/hooks.json`, `.cursor/mcp.json`, `.claude/settings.json`, `.mcp.json`
- `scripts/probe.sh`, `scripts/mcp-echo.ts`, `probe/BLOCKED.md`, `probe/README.md`
- `docs/DEVLOG.md`, `docs/STATUS.md`, `docs/BLOG-LOG.md`, this brief

## Steps
1. `scripts/probe.sh <editor> <event>`: appends `time editor event tool file` to `/tmp/sb-hooks.log`. It always prints valid JSON, and it allows everything except an edit of a file named `BLOCKED.md`, which it denies (Cursor: `{"permission":"deny"}`; Claude Code: `permissionDecision: "deny"`). `sessionStart`/`SessionStart` injects a canary sentence so we can test context injection.
2. `.cursor/hooks.json`: `sessionStart`, `preToolUse` (matcher `Write`), `beforeShellExecution`, `afterFileEdit`. `.claude/settings.json`: `SessionStart`, `PreToolUse` (matcher `Edit|Write`), `PostToolUse` (matcher `Edit|Write`).
3. `scripts/mcp-echo.ts`: a zero-dependency stdio MCP server (JSON-RPC: `initialize`, `tools/list`, `tools/call`) with one tool `sb_echo`. Registered in `.cursor/mcp.json` and `.mcp.json`. No SDK, so there is no lockfile change while B2/B3 run in parallel; M7 adopts the real SDK.
4. Run the tests: (a) the probe script against sample JSON; (b) FalkorDB `algo.WCC`, `algo.pageRank` and the server version; (c) the main chat's own Cursor edits and shell calls; (d) a fresh Cursor Agent chat (the owner) for `sessionStart` and MCP; (e) a headless Claude Code session (`claude -p`) for its hooks and MCP.
5. Record a results table in DEVLOG and the decisions it implies.

## Acceptance criteria
- [ ] DEVLOG has a table: each hook or MCP check → fired / blocked / not fired, with evidence lines from `/tmp/sb-hooks.log`
- [ ] FalkorDB WCC and PageRank calls return rows; the version is recorded
- [ ] A decision is written for F12 (Cursor deny or log-only) and for MCP vs CLI for workers
- [ ] `npm test`, `npm run typecheck` and `npm run lint` still green
