# B3: Core graph (M2 connection + schema + events, M6 feed + edits)

- **Goal:** the core library can connect to FalkorDB, create the schema, write Event nodes with an atomic, gap-free `seq` (the event bus) and read the feed back, all tested against a real FalkorDB. Every later feature writes through this, so FalkorDB is the bus from day one (PLAN §2 "the graph is the bus").
- **Model:** Grok 4.7
- **Branch:** `hack/B3`. Worktree: yes (`../gh-B3`)
- **Read first:** PLAN §2 (data flow), §3 (graph model and indexes), §4 Q7 and Q8, §6 M2 and M6.

The project rule is that **every Cypher string lives in `packages/core/src/queries/*.ts`**, so `graph.ts` contains no Cypher. That is why schema and events live under `queries/` (a small deviation from the file names in PLAN §6 M2).

## Steps
1. `npm install falkordb@^6.8.0 -w @switchboard/core`. This is the official FalkorDB Node client (PLAN §2 stack); it is the only new dependency. Read its README in `node_modules/falkordb` for the exact `connect`, `selectGraph`, `query`, `roQuery` and `delete` signatures before writing code; don't guess.
2. **`graph.ts`:**
   - `connect(opts?: { url?: string; graph?: string })` uses `FALKORDB_URL` (default `redis://localhost:6379`) and `SB_GRAPH` (default `sb_demo`). Returns a small `SbGraph` object: `{ name, query(cypher, params?, opts?), roQuery(cypher, params?, opts?), close() }`.
   - `query` is for writes and `roQuery` (`GRAPH.RO_QUERY`) for reads. Both pass a `timeout` in ms, default **2000** (the server's own default is 1000).
   - Rows come back as plain objects keyed by the RETURN aliases.
   - A connection failure throws an error that says "Is FalkorDB running? Try `npm run db:up`".
3. **`queries/schema.ts`:** `ensureSchema(g)` creates every index from PLAN §3 (range indexes on `File.path`, `Symbol.fqn`, `Agent.id`, `Task.id`, `Event.seq`, `Decision.id`, the edge index on `CLAIMS.until`, and full-text indexes on `Decision(text, why)` and `Lesson(text)`). It also creates the counter node with `MERGE (m:Meta {key:'seq'}) ON CREATE SET m.value = 0`. It must be **idempotent**: calling it twice is fine (catch only the "already indexed" style errors; rethrow anything else).
4. **`queries/events.ts`:** `recordEvent(g, e: { kind, agentId?, onPath?, taskId?, payload?, now? })` → `Promise<number>` (the new `seq`).
   - It runs **one** write query, so the seq bump and the Event creation are atomic (FalkorDB serialises writes per graph). The query increments `Meta{key:'seq'}`, creates `(:Event {seq, kind, at, payload})` with `payload` as a JSON string, and links `-[:BY]->(:Agent {id})` (MERGE the agent), `-[:ON]->(:File {path})` (MERGE the file) and `-[:UNDER]->(:Task {id})` (MERGE the task), but only for the ones given.
   - Export the Cypher as a named, documented constant (for example `RECORD_EVENT`), as every query file does. Keep the optional links simple and readable (for example `FOREACH (_ IN CASE WHEN $agentId IS NULL THEN [] ELSE [1] END | …)`, or one fixed query per shape). Pick the version the owner can explain in two sentences, and add a short comment saying why it is one query.
   - `kind` is one of the values in PLAN §3 (export a TypeScript union type `EventKind`).
5. **`queries/feed.ts` (Q8):** `feedSince(g, last: number, limit = 200)` uses `roQuery` with the Q8 Cypher from PLAN §4. It returns `{ seq, kind, at, payload (parsed), agentId, onLabel, onKey }[]` ordered by `seq`. Also export `latestSeq(g)`.
6. **`queries/edits.ts` (Q7 write part only):** `recordEdit(g, { agentId, path, now? })` → `seq`. One write query that MERGEs the Agent and the File, creates `(a)-[:EDITED {at, seq}]->(f)`, and creates the `edit` Event (BY the agent, ON the file) with the same `seq`. Reuse the seq/Event Cypher from `events.ts`; don't copy it. Collision detection is **not** in this task (it needs Q1).
7. **Tests** (vitest, against the real FalkorDB on `localhost:6379`). Each test file uses its **own graph name** (`sb_test_<file>`), deletes it in `beforeAll`/`afterAll` and calls `ensureSchema`. Required tests:
   - `graph`: `RETURN 1` works; `roQuery` rejects a `CREATE`.
   - `schema`: `ensureSchema` runs twice without error; `CALL db.indexes()` lists the `File.path` and `Event.seq` indexes.
   - `events`: **20 concurrent** `recordEvent` calls (`Promise.all`) return seqs that are exactly `1..20` with no duplicates or gaps. This test proves the bus is safe under concurrency, so keep it. Also: BY/ON/UNDER edges are created only when given.
   - `feed`: after 5 events, `feedSince(g, 2)` returns seqs 3, 4, 5 in order, with the agent id and the `onKey` path; `payload` round-trips as an object.
   - `edits`: `recordEdit` creates the EDITED edge, and its `seq` equals the Event's `seq`.
8. `packages/core/src/index.ts`: re-export `connect`, `ensureSchema`, `recordEvent`, `feedSince`, `latestSeq`, `recordEdit` and the types.
